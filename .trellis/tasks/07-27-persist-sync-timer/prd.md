# 需求：后台自动同步改为「跨重启的 24 小时倒计时」

## 背景

上一个任务（07-27-auto-sync-provider-models）实现了绑定供应商的分组每 24h 后台自动同步。
但当时的定时器是纯内存 `tokio::time::interval(24h)`，随代理生命周期存活：

- 代理停止（退出应用 / 关代理开关 / 改端口重启）→ 定时器销毁并从头计时。
- 结果：只在应用连续运行满 24h 后才触发一次；对「每天只开几小时」的用户，后台同步**永远不会触发**。

## 目标

把「连续运行满 24h」改为「距离上次成功同步已过 24h」，做到跨应用重启累计。
只要一个绑定分组距离上次同步超过 24 小时，代理运行期间就应尽快（在安全启动延迟后）补上同步。

## 需求

1. 每个分组记录「最后一次成功同步时间」，持久化到数据库，跨重启保留。
2. 手动「立即同步」成功、后台自动同步成功，都要刷新该时间。
3. 后台调度器基于该时间判断是否过期（≥ 24h 或从未同步）；只对过期的绑定分组发起上游拉取。
4. 保留「防封号」原则：
   - 代理启动后必须先延迟一段时间（5 分钟）再做第一次检查，绝不在启动瞬间批量打上游。
   - 多个过期分组同批需要同步时，彼此错开（间隔 5 秒），避免突发并发。
5. 未绑定供应商的分组、绑定但供应商被禁用的分组，一律不参与后台拉取（延续既有约束）。

## 验收标准

- AC1：`groups` 表新增可空列记录最后同步时间；迁移幂等、无损，有单测。
- AC2：`perform_sync_bound_group` 成功后写入当前时间；失败（fetch Err）时不写入、不改动分组。
- AC3：后台调度器每小时检查一次；启动后先延迟 5 分钟才做首次检查（启动瞬间零上游访问）。
- AC4：调度器只同步「last_sync_at 为空 或 距今 ≥ 24h」的绑定且启用供应商的分组；未过期的跳过。
- AC5：同批多个过期分组之间以 5 秒间隔错开发起。
- AC6：手动「立即同步」仍可随时触发并刷新时间（不受 24h 限制）。
- AC7：前端 `Group` 类型补充最后同步时间字段；绑定态可展示「上次同步：…」（可选展示，但类型契约必须对齐）。
- AC8：`upstream-access.md` 例外记录同步为新机制（每小时检查 + 5 分钟启动延迟 + 24h 过期判定）。
- AC9：质量门禁全绿：cargo test / clippy / fmt、前端 typecheck / lint / build。

## 非目标

- 不做「启动即补偿拉取」（明确违反防封号原则）。
- 不提供同步周期 / 延迟时长的用户配置项（沿用固定值）。
- 不改变纯镜像全量覆盖、空列表清空、失败保留的既有写入语义。
