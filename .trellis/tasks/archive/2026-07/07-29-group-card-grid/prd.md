# 分组卡片响应式布局

## 目标

将分组页面当前的纵向列表改造成接近 Octopus 分组页面观感的响应式卡片网格，使多个分组更容易浏览和区分，同时保持现有分组业务能力不变。

## 背景与已确认事实

- 当前分组列表位于 `src/pages/GroupsPage.vue`，每个分组以纵向区块展示。
- 用户指定使用响应式网格，而非固定列数。
- 用户要求参考 Octopus 的分组卡片风格，但不展示“轮询、随机、故障转移、加权分配”等策略选择区域。
- model-hub 的分组队列固定按顺序故障转移，现有业务逻辑无需改变。

## 需求

1. 每个分组以独立卡片形式展示。
2. 卡片列表使用响应式网格：窄屏单列、中等屏幕双列、宽屏三列。
3. 卡片展示分组名、思考强度、自动同步状态、模型数量和模型队列。
4. 模型队列继续体现供应商、上游模型和故障转移优先顺序；模型较多时在卡片内部滚动，避免单张卡片无限增高。
5. “配置到 Pi”“编辑”“删除”入口保留并放入卡片操作区。
6. 保留现有新建、编辑、删除、自动同步、队列排序和配置到 Pi 的交互逻辑。
7. 卡片视觉遵循项目现有 happier-ui/Tailwind 风格，以边框、背景和圆角表达层次。

## 范围外

- 不新增轮询、随机、故障转移、加权分配等策略选择界面或配置逻辑。
- 不修改后端、数据库、Tauri API 或分组数据结构。
- 不调整新建/编辑分组对话框的业务逻辑。

## 验收标准

- [ ] 分组页面在窄屏、中等屏幕和宽屏下分别呈现一列、两列和三列卡片。
- [ ] 每张卡片完整显示分组摘要、模型队列及原有操作入口。
- [ ] 模型数量较多时仅卡片内部队列滚动，不破坏页面整体布局。
- [ ] 页面不出现 Octopus 的策略选择区域。
- [ ] 原有分组业务操作行为保持不变。
- [ ] `pnpm lint`、`pnpm typecheck` 和 `pnpm build` 全部通过。
